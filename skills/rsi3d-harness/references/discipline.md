# 纪律：为什么这些约束不能绕

引擎的价值全在"结果可信"上。下面每一条都由测试钉死，绕过去得到的数字就不再是对账依据。

## 四条不变量

| 不变量 | 含义 | 对你的影响 |
| --- | --- | --- |
| **可逆** | `apply(cmd)` 后 `apply(inverse)` 回到**逐字段相同**的状态 | 逆命令是"恢复原值"，不是参数取反（AABB 旋转代数上不可逆）。所以放心试——退回是精确的 |
| **可重放** | `replay()` 与实时状态逐字段相同 | 同一份文档在别人机器上重放得到同一结果 |
| **确定** | `scene_hash()` 内容寻址；日志哈希**不含墙钟** | 同轨迹必同哈希，才能进账本对账 |
| **游标一致** | `state_at(cursor()) == scene()` | `undo`/`redo` 的前提。回滚之后状态是自洽的 |

推论：**没有 op log 的改动不允许落盘**。改完必须走 `scene_edit` / `scene save`，别直接改 JSON 文件——
那样分数曲线无法归因、也回滚不了。

## 告警码（导航，不是错误清单）

| code | 意思 | 常见处置 |
| --- | --- | --- |
| `window.blocked` | 有东西挡住窗户 | 把挡窗的家具挪出挡光带 |
| `layout.intersect` | 两个对象互相穿插 | 挪开或换位置 |
| `bounds.out_of_room` | 对象跑出房间 | 挪回来或缩尺寸 |
| `bounds.floating` | 悬空（离地） | 落到地面 |
| `light.out_of_range` | 灯光强度超出合理区间 | 拉回理想值 |
| `rule.violated` | 违反声明的间距/布局规则 | 按实测值调整 |
| `rule.dangling` | 规则引用了不存在的对象 | 修规则或补对象 |
| `intent.missing` | 意图没写 | 补 `intent` |

**判身份用 code + 节点，不是全文**。数值变了不算新告警；新出现的告警才是这一步的代价。

## 可编辑性（`editability`）

| 值 | 能做什么 |
| --- | --- |
| `full` | 任意命令 |
| `crop-only` | 只能裁剪/删除（高斯、点云这类） |
| `replace-only` | 只能整体替换（烘焙产物这类） |

取值 = **层推导与生产者声明里更受限的那一个**——谁也不能放宽。
给 `crop-only` 的节点发 `transform`，引擎会拒绝并说明原因；**先 `scene_observe` 看清再动手**。

## 证据档与降级

- 观测图带渲染来源档名。**`cpu-raster/v1` 是唯一的证据档**：同平台同构建逐字节可复现，`checkout` 后逐像素回到原样。
- 其它档（将来接的 GPU 档 / 桌面捕获档）**不可复现，不得用于验收**；它们必须登记、必须自报，不得冒充 `cpu-raster/v1`。
- 跨平台**不承诺逐字节一致**（`sin/cos` 的 libm 差异）→ 跨平台评测用 `id pass` 统计与规则指标（整数/有理数运算）。
- **降级必须显式**：取不到 CDN、GPU 上下文丢失、能力不足导致降档，都会写进结论。看到就如实转述，不要静默变差。

## 宿主/客户端给的数值只缩不放

客户端会自报能力（`?px=WxH` `&fps=` `&cap=`），但服务端**只按更严的那个来**：
像素预算等比缩小、帧率取更小值、渲染档只降不升。**别指望参数被放大**。

## 常见坑（都实测过）

- **别用 `log` 当现状**：它是历史与归因表；现状看 `observe` / `show`。
- **一次只改一件事**：批量命令中途被拒时，前面的仍然生效——结果会说明，但读起来比单步麻烦。
- **观测图不是截图**：它是渲出来的确定性像素，不是屏幕捕获；所以能当证据，也能比对。
- **静态资源免令牌但数据口要令牌**：`/healthz`、`/`、`/client.js`、`/contract` 公开；
  `/observe` `/command` `/stream/*` `/snapshot.gltf` `/mesh.glb` 一律要 `?token=`。
- **side-car 不在旁边就画包围盒**：`<场景名>.mesh.glb` 与场景放同一目录，否则浏览器只画代理盒（不白屏，但也不是真网格）。
