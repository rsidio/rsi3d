# MCP 九工具

这是驱动引擎的**首选**路径。九个工具共享同一份内核，所以 MCP 看到的告警、测量值、哈希与 CLI 逐字一致。

| 工具 | 干什么 | 副作用 |
| --- | --- | --- |
| `scene_open` | 打开场景/文档（或内联场景 JSON），设为当前会话 | 幂等 |
| `scene_observe` | 节点表（含**可编辑性**）、灯光、间距实测、挡窗者、全部告警、哈希 | 只读 |
| `scene_edit` | 执行一条或多条命令，返回新版本号、**逆命令**、新增告警 | 有 |
| `scene_rollback` | `rev` 跳到某一版（best-so-far）／`undo` 退回 N 步 | 有 |
| `scene_history` | 日志 + 归因表：谁改的、为什么、期望什么、新增哪些告警 | 只读 |
| `scene_diff` | 两版之间精确差异（对象与灯光属性） | 只读 |
| `scene_render` | **直接返回观测图（PNG）** + 每个对象可见像素 + 窗前挡光带被遮挡 % | 只读 |
| `scene_save` | 落盘成文档（含日志，可重放对账） | 幂等 |
| `scene_verify` | 可复现性自检：重放一致 / 全版本可重放 / 往返哈希 / 快照 / 游标 | 只读 |

## 用法要点

**`scene_open`** —— `file` 传相对 `--root` 的路径；也可直接传一段内联 `scene` JSON（不需要文件）。
带 `spec=rsi3d-document/v1` 的按文档读（**保留历史与版本**，从打开时的版本继续），否则按场景读（rev 0 开始）。
> 想保留历史就用文档；想从干净场景开始就用场景 JSON。

**`scene_observe`** —— 判断好坏的**唯一依据**，不要凭记忆猜场景内容。
同版本重复观察必得同 `scene_hash`，所以它可以当基准来比对改动效果。
注意 `editability`：`crop-only` / `replace-only` 的节点**不能** `transform`（引擎会拒绝并说明原因）。

**`scene_edit`** —— 强烈建议**一次只放一条命令**，这样每一步的因果才清楚。
`reason` 必填；`expect` 用来事后核对你的判断对不对。
返回里两个东西要看：**`inverse`**（逆命令，恢复原值）与 **`new_warnings`**（这一步新增的告警）。
中途某条被拒时前面的改动仍然生效，结果里会明确说哪些生效、哪些没执行。

**`scene_rollback`** —— `rev` 跳到某一版（RSI 的 best-so-far 就该用它），`undo` 退回 N 步。
回滚本身也是一条命令，会进日志，所以**回滚之后还能再回滚回来**。

**`scene_render`** —— 要"量出来"的数字就用它：可见像素、窗前挡光带被遮挡的百分比。
返回值带渲染档位，`cpu-raster/v1` 才是可复现的证据档。

**`scene_save`** —— 把当前场景连同**完整命令日志**存成文档；不给 `file` 就存回打开时的源文件。
目标已存在且不是源文件时需要 `overwrite=true`。

**`scene_verify`** —— 需要"结果可以拿去对账"的证据时用：日志重放是否等于当前状态、每个版本是否都能重放、
落盘往返后哈希是否不变、快照与重放是否一致、游标是否自洽。

## 约束

- **写路径限在 `--root` 之内**（`../../etc/passwd` 这类会被拒）。引擎只能读写被授权的工作目录。
- 失败是 `isError: true` + 错误码 + **当前状态**——读得到的部分才能让你改对。
- `stdout` 严格只有协议报文（日志走 stderr）。
